## Common patterns
- **Missing `receipt-ok` Business Events**: All 6 failures in the `wisp` suite consistently fail at `check_wisp_session_timers_del_and_rts_were_sent` because no event with business process `receipt-ok` and status `RT_SEND_SUCCESS` is found.


## Cross-suite correlation

- **WISP Event Pipeline Outage vs. Checkout Behavior**: 
  - All failures in the **wisp** suite point to a systematic absence of the `receipt-ok` (`RT_SEND_SUCCESS`) event across single payments and cart payments. This strongly indicates a service outage or configuration issue in the event-logging/receipt-dispatch component handling WISP sessions.
  - The **checkout** suite failures highlight issues downstream or during UI interaction (PSP element timeouts and unexpected error modal headers). While distinct from the backend WISP event processing issue, both suggest potential environment instability in UAT services.
  - **FDR-3** passed completely with no issues identified.
