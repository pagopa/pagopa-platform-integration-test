## Common patterns
- **Systemic Receipt Generation Failure (`receipt-ok` missing)**: All 5 failures in the `wisp` suite share the exact same assertion error (`There are not events with business process receipt-ok`). The receipt sending pipeline (`RT_SEND_SUCCESS`) or the underlying event-store/event-bus integration is failing systematically across all WISP payment flows regardless of transfer type or stamp configuration.

## Cross-suite correlation

Across the analyzed suites, two distinct failure patterns emerge:

1. **WISP Suite Systemic Backend Failure (Application Bug)**:
   - **Pattern**: Every failure in the `wisp` suite fails at `check_wisp_session_timers_del_and_rts_were_sent` expecting a `receipt-ok` event with status `RT_SEND_SUCCESS`.
   - **Impact**: Completely blocks confirmation and receipt processing verification across WISP single and cart payments.
   - **Action**: Check receipt generation microservice health, message queues (Event Hubs/Kafka), and downstream RT dispatcher logs in UAT.

2. **Checkout Suite UI / Environment Instability**:
   - **Pattern**: Multiple E2E UI tests timing out while trying to interact with specific UI elements (such as `#psp-radio-PPAYITR1XXX`).
   - **Impact**: Causes UI payment activation flows to fail unpredictably.
   - **Action**: Verify UAT frontend/backend latency for the `/lista-psp` endpoint and validate that PSP mock/test data is active.
