    Verifica del contratto UC

    Questa matrice verifica uc-workflow/v1, non specifica comportamenti di prodotto. Gli identificativi sono astratti: nessun UC, dato reale, feature della suite o esempio UC-to-feature approvato viene introdotto. Le tre skill restano responsabili degli output del contratto.

    Livelli di verifica

    1. Asset statici: metadata, link, colonne e sezioni dei template, permessi, invalidazione, enum e presenza delle regole operative concordate.
    2. Sintassi isolata: il parser Behave legge frammenti artificiali in memoria con TODO, outline parziali, Background e piu verifiche nello stesso scenario. Non esegue step, transazioni o test della suite; non dimostra idoneita dei dati.
    3. Comportamento dell'agente: una prova richiede un UC umano, fonti ammesse, percorsi/input e run confermati. Confrontare gli artefatti effettivi con la matrice, registrando risultati, metodo, revisioni ed evidenza. Non dedurre il comportamento dell'agente dalla presenza di una frase nella skill.

    I test di sviluppo, esterni al QA-analyst, sono in test_uc_workflow_contract.py. Usano il runner dei test unitari e il parser Behave gia adottati dal progetto:

    .\.venv\Scripts\python.exe -m pytest tests\unit\qa_workflow\test_uc_workflow_contract.py -q

    Eseguire dalla root con pytest e le dipendenze del progetto disponibili nel virtualenv di sviluppo. I tool di sviluppo mancanti non sono capacita operative aggiuntive dell'analista.

    L'analista non esegue questo comando: i suoi permessi terminale non cambiano. Nessun verificatore o matcher runtime viene installato nel workflow. Gli assert sulle clausole e sulle tabelle sono regressioni del contratto documentale, non un motore sostitutivo che simula l'agente.

    Regressioni analista e orchestratore (ADR-02 - ADR-07)

    Lo stesso test di contratto verifica anche routing, permessi, gate e identita nei documenti dell'analista e dell'orchestratore. Come per V-01 - V-36, i casi seguenti sono risultati attesi, non prove di un'esecuzione reale dell'agente.

    Caso Richiesta o stato Risultato atteso
    A-01 Feature allegata senza azione chiara Chiede review/modifica/creazione, senza dedurre permesso di modifica dall'allegato
    A-02 QA-analyst invoca review-feature-files direttamente Applica la skill senza autodelega; nessuna feature creata o modificata
    A-03 Review con report Markdown richiesto Conferma il percorso se manca, salva solo il report e restituisce elementi ACE senza scrivere trace
    A-04 Review solo in chat Nessun report o feature scritto; nessuna delega a engineer/runner/closer
    A-05 Correzione esplicita di file nominati Nessuna seconda autorizzazione generica; preserva lo scope e spiega impatto sui binding
    A-06 Correzione di feature registrata UC Riconcilia tramite il proprietario; se incompleta, invalidazione circoscritta e nessun vecchio ready mantenuto
    A-07 Creazione da documentazione non UC Stesse garanzie sulle fonti, oracle e dati; nessun UC o registro UC inventato
    A-08 Suite di migrazione fornita come input non UC Evidenza dell'implementazione corrente, non requisito implicito; nessuna eccezione per traduzione UC
    A-09 Analista restituisce bozza o solo changes-complete Nessuna implementazione automatica; orchestratore verifica readiness per file e confini della richiesta
    A-10 Solo un sottoinsieme delle feature e pronto Implementazione parziale soltanto con autorizzazione esplicita dell'umano
    A-11 Nuova richiesta ACE riprende una run UC Nuovo ACE task_id ma identita e percorsi UC invariati; nessuna migrazione dello schema
    A-12 Scrittura report o registro fallita Errore e file realmente salvati espliciti; nessun successo o stato corrente inventato

    Stato delle prove

    La matrice contiene risultati attesi, non risultati osservati. Nessuna riga attesta una run reale solo perche esiste qui. I test statici/sintattici possono essere eseguiti senza queste run; una prova agente deve specificare il caso, gli input confermati, i percorsi effettivi e l'esito osservato nel suo report. Una valutazione su un caso iterato non dimostra generalizzazione.
